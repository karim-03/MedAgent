# Knowledge Base Findings — P2 (Milestones 9-11)

## Sourcing

8 documents, all fetched live on 2026-07-26 from official sources chosen to
map directly onto the ML model's actual features, not generic overview
text:

| Document | Maps to feature(s) |
|---|---|
| CDC — About Heart Disease | general context, `target` |
| CDC — Heart Disease Risk Factors | `age`, `sex`, `trestbps`, `chol`, `fbs` |
| NHLBI — Coronary Heart Disease Diagnosis | `restecg`, `thalach`, `oldpeak`, `slope`, `ca` |
| NHLBI — Angina | `cp`, `exang` |
| NHLBI — Blood Cholesterol Diagnosis | `chol` |
| NHLBI — High Blood Pressure Diagnosis (incl. BP category table) | `trestbps` |
| NHLBI — Heart Tests (ECG, stress test, angiography, echo) | `restecg`, `thalach`, `oldpeak`, `slope`, `ca` |
| WHO — Cardiovascular Diseases (paraphrased) | global context only |

7 of the 8 are U.S. federal government works (CDC/NHLBI), which are public
domain under 17 U.S.C. §105 — this is exactly why U.S. federal health
agencies are the standard choice for offline/redistributable medical RAG
corpora, and why the content in this knowledge base can be stored and
redistributed close to verbatim with full attribution. The WHO document is
not a U.S. government work, so it's deliberately written as an original
paraphrase of publicly reported WHO statistics rather than a verbatim
copy — see the note inside that file for why it's still worth including
(global-context framing) despite being treated as a lower-precision
source. Full provenance table: `data/knowledge_base/sources_manifest.md`.

## Chunking

43 chunks from 8 documents, chunked along `##` section boundaries (one
clinical concept per chunk) rather than a fixed-token sliding window, with
long sections further split by paragraph at a 180-word soft budget. Chunk
sizes ranged 12–228 words, averaging 86. Every chunk carries its source
title, URL, and retrieval date as metadata, not just raw text — this is
what makes citation possible at query time.

## Embedding and indexing

- Embedding model: `sentence-transformers/all-MiniLM-L6-v2`, CPU-only (see
  `docs/architecture.md` Section 5.5 for the VRAM-budget rationale).
- Index: FAISS `IndexFlatIP` over L2-normalized vectors (cosine similarity
  via inner product). Exact search, not approximate (IVF/HNSW) — at 43
  chunks there's no scale problem to solve, and approximate indexing would
  only add a recall/accuracy trade-off for no benefit at this size.
- Metadata stored in a parallel JSON file keyed by FAISS's internal
  integer ids, since FAISS itself only stores vectors.

## Retrieval

`rag/retrieve.py` returns an **empty list**, not fabricated or
low-relevance content, when nothing clears a similarity threshold
(default 0.25) — this matters for a clinical tool: the agent must be able
to say "no supporting evidence found" rather than always returning
something. Every result carries a ready-to-display citation string:
`"{title} ({source}), section \"{section}\" — {url}"`.

## Verification — and an honest environment note

The dev sandbox this was built in has a restricted network egress
allowlist that does not include `huggingface.co`, so the real embedding
model can't be downloaded from inside this specific tool environment.
This is a property of the build sandbox, not of your machine — the same
way the project already assumes one-time internet access to pull the
Ollama LLM, `sentence-transformers` needs one-time internet access to
download `all-MiniLM-L6-v2` (~80MB) the first time `rag/build_index.py`
runs; after that it's cached locally (`~/.cache/huggingface`) and runs
fully offline, consistent with the project's offline constraint.

To still verify the chunking → index → retrieve → citation pipeline
end-to-end on the real knowledge base content without that download, a
sandbox-only substitute encoder (TF-IDF + truncated SVD — real
dense vectors, no network needed) was used to smoke-test the same FAISS
index/search/metadata code path. Results were sensible: querying "chest
pain during exercise" correctly top-ranked the angina and stress-test
chunks; "what does high cholesterol mean" top-ranked the cholesterol risk
factor chunk. This confirms the plumbing is correct — it is not a claim
that TF-IDF matches MiniLM's retrieval quality, which is why the shipped
`rag/build_index.py` and `rag/retrieve.py` use the real embedding model,
not TF-IDF. Unit tests that require the real model
(`tests/unit/test_rag.py`) are written to run for real and are skipped
(not failed) only when the model isn't reachable/cached — on your machine,
with normal internet access, they'll execute and check actual semantic
retrieval quality, not just plumbing.
